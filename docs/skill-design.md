# Skill 设计说明

## 解决的问题

该 Skill 让一个不了解历史项目的 AI 能够从论文和 panel 请求开始，找到权威代码与数据，确定科学边界，制作最小 Figure-ready 输入，按统一接口实现绘图后端，生成当前执行证据和双语手册，并完成可审计发布。

## 触发条件

应该使用：论文 figure/panel 复现；已有复现包修复；作者代码适配为后端；科学绘图交付审计；发布 ZIP 整理。

不应该使用：普通业务图表；仅对已有图片做美化/抠图；纯论文解读；完整分析平台或 runtime 打包；无法识别论文/panel 且用户只想要相似风格图片。

## 信息架构

- `SKILL.md`：必须执行的边界、阶段、决策门和读取路由。
- `references/`：来源模型、合同、参数化、视觉、报告、发布和经验细节。
- `templates/`：立项表、规则来源记录、检查清单；用于思考与验收。
- `assets/protected-template/`：受保护的实际 case 脚手架，只复制不直接改。
- `examples/`：三个成功案例和边界/失败模式，不进入核心默认值。
- `scripts/`：确定性的建案、静态审计、视觉比较和模板哈希工具。

## 核心判断

1. 作者代码能否直接定位 panel？不能则降低来源等级或停止。
2. Figure-ready 输入能否真实地从作者对象推导？不能则不得标 `AUTHOR_DERIVED`。
3. routine plot 是否需要大型数据？不需要则排除；需要重建且用户有需求才保留 prepare。
4. 差异是否影响科学含义？科学差异回到合同与数据，显示差异冻结科学层后修复。
5. 每个参数影响哪个失效范围？无法说明则不对用户暴露。
6. 当前证据是否来自当前代码和输入？不是则删掉或标 stale，不能继承 PASS。

## 输出

输出不是机械固定文件数，而是一组不可缺失的角色：身份与边界、运行入口、稳定后端、机器合同、来源追踪、真实 Figure-ready 输入、当前运行证据、参考 panel、依赖记录和双语报告。条件资源只有在确有作用时存在。

## 设计取舍

Skill 核心保持短；所有详细规则以明确链接按阶段读取。受保护脚手架仍保留，因为它已经在案例中验证了命名、报告和接口骨架；但模板占位内容不得原样成为交付。脚本只做可确定的机械检查，不替代科学来源判断和人工视觉验收。
